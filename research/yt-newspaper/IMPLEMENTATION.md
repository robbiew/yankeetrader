# Galactic newspaper and public event journal

Computer option 8 prompts for Today/Yesterday and retries invalid input; lowercase
T/Y works. Compact `NEWS` defaults to Today; `NEWS TODAY`, `NEWS T`, `NEWS YESTERDAY`
and `NEWS Y` select explicitly. The classic interface also accepts explicit NEWS
arguments outside the numbered computer menu. Headers show the selected UTC date,
and an empty day says no news is retained. Queries spend no resources and never
rewrite the journal. Enter advances a five-entry page; Q (or other nonblank input)
stops. Paging keeps one snapshot/date while rechecking the live ship generation
and deadline before each page. A partial terminal write never changes history.

## Proven producers and privacy

Every successful authenticated login, including an accepted first login or
replacement, records one `login` event within that same locked transaction.
Aborted registration, rejected replacement and expired login transactions record
nothing. Failure of terminal output after commit does not undo a real login.
Player-facing team creation uses `CreateTeamWithNews`: journal preconditions are
checked before creating a team, then the event is appended without another
fallible step. Store rollback discards the action and its event together. A save
failure after world replacement remains a typed committed durability warning;
the persistent event stays aligned with the visible action.

Only two event kinds are accepted: login and team-created. Each stores ID, UTC
time and public alias; team-created additionally stores public team number/name.
These snapshots survive later renames and membership changes. There is no generic
text field. Authentication identities, invitation passwords/hashes, docking or
landing tokens, account/planet balances, private radio and session spy intelligence
cannot enter the event projection. All living callers can read the same public
journal. No new news event is generated by reading or by maintenance itself.

The displayed login/team-created wording follows the verified DOS slice; date
headings, pagination and the typed journal are deliberate modern adaptations.
First-time login is recorded as login, not the unverified original registration
message. Combat, deaths, ownership changes, planet creation, recruitment and
NPC events are not recorded or advertised as recovered newspaper producers yet.

## Retention, ordering and clocks

The journal retains today and yesterday by UTC calendar date, with a global cap
of 1,024 newest entries across those dates. Successful append or forward daily
maintenance removes older entries. At capacity, appending evicts the oldest event;
this can remove yesterday's entries on a busy day. Missed days do not substitute
"last available day" for Yesterday. Repeated/same-day or backward maintenance
uses the existing guard and leaves history untouched, fixing the observed DOS
fallthrough/rotation defect.

IDs increase across eviction and expiry and are never reused. Timestamps are
nondecreasing; new writes/queries reject a clock before world creation, the saved
maintenance date or the latest retained event. This avoids silent backdating
or relabeling when a server clock moves backward; clock correction is required
before those requests can proceed. Event clocks are sampled inside their locked
transactions. The journal's public labels are bounded printable ASCII and are
validated on every load/save, along with kinds, sequence, UTC offsets, ordering,
retention and capacity. The latest saved maintenance day is also a retention
horizon, even when the retained journal is empty.

## Save migration

World version **12** adds `News` and `NextNews`. Supported versions 1–11 upgrade
in memory through the existing migration chain and receive an empty journal with
next ID 1. A view does not rewrite an old file; the next successful update saves
version 12. Existing players, teams, assets, radio, score caches and spy behavior
are preserved. Historical login dates and current ownership are not turned into
fabricated old news. A legacy header carrying newspaper state is rejected rather
than silently discarding or misinterpreting it. Older binaries cannot read version
12: back up the stopped world and upgrade all nodes together; rollback requires
the matching backup and binaries.

## Validation

Game tests cover UTC midnight/date gaps, real public snapshots, public cross-player
access, private-field exclusion, read immutability/copy isolation, capacity/ID
retention, forward/repeated/backward maintenance, clock rejection and malformed
archives. Store tests cover old-save migration/no backfill, atomic rollback,
concurrent writers and committed directory-sync warnings. Door tests cover both
interfaces, real team creation, read paging/stop, stale generations, expiry,
aborted login and failed output. Existing legacy upgrade tests preserve their
original-format inputs and now assert version 12 as the current saved format.

`scripts/smoke_newspaper.py` drives real GoDoors PTYs through compact and classic
computer 8, invalid/lowercase selection, public team events, password exclusion,
reconnect, Yesterday reading, version-11 migration, paging and maintenance replay.
Its transcript is `evidence/newspaper-smoke.txt`; CI runs it alongside the
[preserved DOS evidence verifier](RECOVERY.md). Local PTY and cross-build checks
remain distinct from native/live BBS acceptance. Exact DOS color/paging/Ctrl-X
behavior and additional event producers remain research boundaries.
